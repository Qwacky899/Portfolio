GAME / SALON & FASHION

Boho Salon

A salon game with two ways to play: be the model, or provide the services. Styling, service stations, quests, saved looks, and runway moments make the space more than a showcase.

My work includes the service architecture and a substantial catalog and saved-looks update, with server validation around who can style whom. The redevelopment also recovered selected game code from Studio into a careful Rojo workflow.

03 / TECHNICAL APPROACH

Play first.
Structure underneath.

The most compelling interface is a game that keeps working. These patterns are visible in the repository-backed projects, especially Boho Salon, Catalog Runway, and The Lab.

PLAYER ACTION→CLIENT INTERFACE→NETWORK VALIDATION→SERVER SERVICES→PLAYER DATA
01 / AUTHORITY

Rules belong on the server.

Game actions are checked where the game state lives. Boho’s styling and catalog work validates the player and target; The Lab’s building system validates edits and revisions.

02 / OWNERSHIP

Clear code and Studio boundaries.

Rojo and Git own the code that can be safely mapped, while authored worlds and assets remain in Studio. That boundary keeps iteration deliberate across large experiences.

03 / CONTINUITY

Systems designed to keep state.

Catalog Runway and Boho Salon use service layers and profile-backed player data for progression and cosmetics. The interface stays connected to the systems behind it.
